```markdown

```

---

## AI 输出：澄清问题

1. **用户规模**：预计多少管理员使用？是否需要角色权限（如只读 vs 可发消息）？
2. **企业规模**：公司员工大约多少人？部门层级大概几层？
3. **企微应用**：是否已在企微管理后台创建「自建应用」？是否有 corpId、AgentId、Secret？
4. **通讯录同步**：是每次打开页面实时拉取，还是定时同步到本地数据库？
5. **发消息场景**：仅文本消息，还是需要图文/ Markdown？是否需要发送记录？
6. **部署环境**：内网部署还是公网？是否有固定域名（企微回调需要）？
7. **MVP 时间**：希望多久出第一版可用？
8. **单企业还是多企业**：第一版是否只服务本公司一个 corpId？

---

## AI 输出：假设清单

| 假设 | 需确认 |
|------|--------|
| 单企业单 corpId，不做多租户 | 是 |
| 管理员 3～5 人，暂不做细粒度 RBAC | 是 |
| 员工规模 200～2000 人 | 是 |
| 通讯录同步到本地 DB，支持手动触发同步 | 是 |
| MVP 仅支持文本应用消息 | 是 |
| 内网或 VPN 访问，暂不对公网开放 | 是 |
| 已有企微自建应用及 API 凭证 | 待确认 |

---

## AI 输出：风险与矛盾

- **风险**：企微 API 有频率限制，全量同步大通讯录可能较慢 → 建议增量同步 + 后台任务
- **风险**：Secret 等凭证需加密存储
- **矛盾**：「实时拉取」vs「本地同步」—— 建议 MVP 用本地同步 + 手动刷新，列表读本地 DB

---

## AI 输出：MVP 建议

**应包含：**
- 管理员账号密码登录
- 企微应用凭证配置页
- 手动触发通讯录同步
- 部门树 + 成员列表 + 搜索
- 向选中成员/部门发送文本消息
- 同步日志、发送记录（简单列表）

**不应包含（v1）：**
- 客户联系、外部群
- 审批 / 打卡 / 汇报
- 消息模板管理
- 多企业、多 corpId
- 企微 OAuth 扫码登录（管理员用本地账号即可）
