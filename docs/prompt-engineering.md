# 提示词工程

## 三层提示词体系

提示词不是孤立的，而是按层次组织：

```text
┌─────────────────────────────────────────┐
│  Layer 1: 项目级规则 (Cursor Rules)      │  ← 从 Spec/Design 提炼：技术栈、风格、禁止事项
├─────────────────────────────────────────┤
│  Layer 2: 工作流 Skills                  │  ← 规划 → 实现 → 验证 的标准流程
├─────────────────────────────────────────┤
│  Layer 3: 单次任务提示模板               │  ← 每次开发时填：目标、文件范围、验收条件
└─────────────────────────────────────────┘
```

### Layer 1：项目级规则

放在 `.cursor/rules/`，持久生效。

示例约束：

- 只用 TypeScript
- API 必须带错误处理
- 禁止修改 `.env`
- 不编造不存在的依赖

### Layer 2：工作流 Skills

定义每个阶段 AI 的行为模式：

- 先 Plan 再 Code
- 改完必须跑测试
- 大功能先拆 PR
- 当前阶段禁止进入下一阶段

### Layer 3：单次任务提示

每次开发任务使用固定模板：

```markdown
## 目标
[从 Spec/Design 摘一段]

## 范围
- 只改：src/xxx/
- 不改：数据库 schema / 其他模块

## 验收
- [ ] 能本地启动
- [ ] 通过 xxx 测试
- [ ] 无新增 lint 错误
```

## 从想法到设计文档：四轮对话

**不建议一次生成完整设计文档**，推荐分四轮：

```mermaid
flowchart LR
    A[想法草稿] --> B[澄清与范围]
    B --> C[方案对比]
    C --> D[详细设计]
    D --> E[人工审核修订]
```

| 轮次 | 目的 | 禁止事项 |
|------|------|----------|
| 第一轮：澄清 | AI 提问、补全假设 | 不写设计、不写代码 |
| 第二轮：方案 | 2～3 种路线对比 | 不写完整接口/表结构 |
| 第三轮：设计 | 按模板输出完整设计文档 | 不写实现代码 |
| 第四轮：修订 | 按反馈只改指定章节 | 不重写无关章节 |

完整提示词见 [templates/prompts.md](templates/prompts.md)。

## 好提示词的五个原则

1. **先约束角色**：「产品设计搭档」「架构师」「评审员」，不要泛泛的「帮我写文档」
2. **先约束阶段**：「不要写设计，先提问」「只写第 5 章」
3. **固定输出格式**：章节模板、表格、checklist，减少 AI 自由发挥
4. **要求显式假设**：逼 AI 把脑补写出来，方便你否定
5. **要求自我质疑**：加一句「列出 3 个本设计最大的风险或漏洞」

## 质量增强句（可加在提示词末尾）

```markdown
- 如果需求有矛盾，先指出矛盾，不要默默选一个
- 每个 P0 功能必须有对应的验收标准
- 技术选型要说明「为什么不选常见替代方案」
- 输出末尾附：【你需要我确认的 5 个问题】
- 输出末尾附：【若资源减半，应砍掉哪些功能】
```

## AI 擅长 vs 人需要把关

| AI 擅长 | 人需要把关 |
|---------|------------|
| 结构化、补全章节 | 真实用户是否需要这些功能 |
| 多种方案对比 | 业务优先级、砍范围 |
| 接口/表结构草案 | 合规、成本、团队能力 |
| 发现遗漏和风险点 | 最终拍板、否决错误假设 |
| 保持一致性（多轮修订） | 是否过度设计 |

**设计文档可以 AI 起草，但「做什么、不做什么、用什么方案」必须人确认。**

## 与后续 AI 编程的衔接

```text
想法 → AI 澄清 → AI 设计文档（人审核）
                    ↓
            提炼成 Cursor Rules（技术约束）
                    ↓
            按模块拆任务（每任务引用设计文档对应章节）
                    ↓
            AI 写代码 + 按文档验收
```

设计文档里应写清：

- **模块边界**（任务提示写「只改 xxx 模块」）
- **验收标准**（任务提示写「完成标准 checklist」）
- **明确不做**（任务提示写「禁止范围」）
